One row per suburb, computed from the full listing history (including the 2-year sold sweep) — not just what's browsable in Data Table. Build a filter below (field / condition / value per row, the left-hand toggle sets AND/OR for that group, ">" nests a condition into a sub-group with the row above it) and save it as a named Strategy to reuse later. Tick rows (checkbox column) to Compare or Add to Shortlist. Price growth (1mo/6mo/1yr/2yr) compares median sold price across two equal-width windows ending today, e.g. 1yr growth is the last ~6 months vs the ~6 months before that — 1mo especially will be blank for lower-volume suburbs, since it needs 3+ dated sales on each side of a ~2-week split. See suburb_columns in config.yaml for the full methodology, and the Data Definitions tab for what every column here means.

Suburbs you've explicitly added via "Add to Shortlist" in Explore suburbs — not affected by any filters there. Tick rows to Compare or Remove. "Load Shortlist" swaps in a previously saved named list; "Save as Shortlist" snapshots the current one under a name so you can build up more than one (e.g. per strategy or state) and switch between them.

Suburbs with at least one currently-For-Sale block worth subdividing at a profit, ranked by a profitability index (best opportunity's profit × confidence). Resale value per new lot comes from actual recent vacant-land sales near the resulting lot size — not a fixed assumption. Subdivision cost and stamp duty buffer are yours to set above; profit and rankings update live. Click a suburb to see its listings, and click a listing to see the comparables used. See references/subdivision/context.md for the full methodology.

All assumptions are the plain inputs below (nothing hidden) — change any of them and every output recalculates instantly. Save a scenario to keep a running list of properties you're comparing.
